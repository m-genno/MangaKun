# 漫画作成スキル（MangaKun）

ストーリーから漫画を作り、修正を重ねて、Kindle（KDP）用のファイルまで書き出す。
Claude がネーム（コマ割り・構図・セリフ）を考え、Gemini がコマの絵を描き、スクリプトが吹き出しと縦書きのセリフを入れてページにする。

## 必ず守ること

- **やさしい日本語で話す。** 使う人は PC や AI に不慣れなことがある。「YAML」「スクリプト」「API」「コマンド」などの言葉は使わず、「台本」「絵を描く」「ページを作る」のように言う
- 質問は**まとめて1回**で聞く。何度も聞き返さない
- **画像生成はお金がかかる**（1枚約15円）。確認モードでは、生成の前に枚数と金額の目安を伝えてから進める
- 作品の状態はすべて作品フォルダの `manga.yaml` に保存する（書き方は [manga_yaml.md](manga_yaml.md)）。会話が途切れても、これを読めば続きから再開できる
- `.env`（API キー）は読まない・表示しない・書き換えない
- スクリプトは**リポジトリ直下**（`.claude` フォルダがある場所）で `uv run .claude/skills/manga/scripts/<名前>.py ...` のように実行する
- 作品フォルダは**リポジトリ直下に半角英数字の名前**で作る（例: `panya-no-hana`）。Kindle Previewer はパスに日本語があると開けない
- 実在の人物・既存の漫画やアニメのキャラクター・作家名を画像生成の指示に入れない

## 道具（scripts/）

| スクリプト | 役割 |
|---|---|
| `gen_panels.py <作品>` | manga.yaml からキャラ設定画・コマ・表紙の絵を生成（`--characters` / `--cover` / `--pages` / `--panels` / `--retake` / `--extra` / `--dry-run` / `--usage`） |
| `compose_page.py <作品>` | ページを合成（`--all` / `--page N` / `--debug` / `--info`）。`--list-layouts` でコマ割り一覧 |
| `export_kindle.py <作品>` | 表紙・EPUB・PDF・一覧画像を `output/` に書き出す |
| `check_epub.py <EPUB>` | EPUB の検証（EPUBCheck と Kindle 変換） |
| `open_file.py <パス>...` | 画像やフォルダを開いてユーザーに見せる |
| `gen_image.py` | 1枚だけ自由なプロンプトで生成（通常は使わない） |

画風のプリセットは [styles.md](styles.md)、設定値（モデル・上限・ページ寸法）は `config.yaml`。

## 作業の流れ

### 0. どの作品か決める

- 「以下の漫画を作って」など新しい依頼 → 新しい作品フォルダを作る（タイトルをローマ字にした名前）
- 続きの作業 → リポジトリ直下で `manga.yaml` のあるフォルダを探す。1つならそれ、複数なら「どの作品ですか？」とタイトルで聞く。`status` を見てどこから再開するか決める

### 1. 入力を確認する（status: input）

| 項目 | 必須 | 無いとき |
|---|---|---|
| ストーリー | ○ | 数行のあらすじでよい |
| ページ数 | ○ | 表紙は別に数える |
| 登場人物 | ○ | 名前・性格・見た目 |
| テイスト（画風） | | styles.md から提案（迷ったら「ほのぼの」） |
| カラー / モノクロ | | カラー |
| モード | | 確認モード |

- 「おまかせで」「全部まかせる」「最後まで作って」などがあれば**おまかせモード**（後述）
- 確認モード: 足りない必須項目と、画風の提案をまとめて1回で聞く
- 決まったら作品フォルダと manga.yaml（title・file_name・mode・color・style・style_prompt・synopsis・characters）を作る。キャラの `appearance` は英語で、髪型・髪色・目・アクセサリー・服の色と形まで具体的に書く（服装は作品を通して固定する）

### 2. ネームを作る（status: name）… 無料

1. `compose_page.py --list-layouts` でコマ割りを見て、ページごとにレイアウトを選ぶ
   - 1ページ 3〜6 コマ。見せ場は大きいコマ（`1_splash`、`3_bottom_wide` など）
   - 右綴じでは、偶数ページ（左ページ）の後でページをめくる。驚きや場面転換は**奇数ページの最初のコマ**に置くと効果的
2. 各コマの `note`（日本語の説明）・`characters`・`scene`・`shot`・`space`・`bubbles`・`sfx` を manga.yaml に書く（[manga_yaml.md](manga_yaml.md) の「セリフの書き方」を守る）
3. `compose_page.py <作品> --all` を実行する。絵がまだないコマは灰色の仮コマになり、コマ割りと吹き出しの配置を無料で確かめられる
4. 確認モード: ページごとのあらすじとセリフを文章で見せ、`open_file.py <作品>/pages/p01.jpg` で仮ページも開いて「この内容で進めてよいですか？」と聞く。直しがあれば直して再提示する

### 3. キャラ設定画を作る（status: characters）

1. `gen_panels.py <作品> --characters` で登場人物ごとに1枚（正面・横・後ろ・表情3種）
2. Read で各設定画を見てチェックする: 文字が入っていない / appearance の通り / 3方向と表情がそろっている。ダメなら `--characters --only <id> --retake --extra "<直す点>"`
3. 確認モード: `open_file.py` で設定画を開き、`gen_panels.py <作品> --dry-run` で出る**コマの枚数と金額の目安**も伝えて「このキャラで全ページの絵を描いてよいですか？」と聞く

### 4. コマの絵を描く（status: panels）

1. `gen_panels.py <作品>` で絵のないコマを全部生成する（4枚ずつ並行。数分かかるので、始める前に「数分かかります」と伝える）
   - 終了コード 3（上限超え）なら止まって、枚数と金額を伝えてユーザーに相談する。了承されたら `--force`
   - `NG` のコマは内容を見て `scene` の言い回しを変えて再実行（安全フィルタに引っかかったときは、暴力的・肌の露出などと誤解されそうな言葉を言い換える）
2. **自己チェック**: 生成したコマを全部 Read で見る。NG の条件:
   - キャラが設定画と別人に見える（髪型・髪色・アクセサリー・服・年齢）
   - 絵の中に文字・枠線・吹き出し・コマ割りが描かれている
   - `space` に指定した場所が空いていない（吹き出しを置くと顔や大事な物が隠れる）
   - 手・指・顔が大きく崩れている、`scene` の内容と違う
3. NG のコマは `--panels <id> --retake --extra "<直す点を英語で>"` で作り直す。1コマにつき `config.yaml` の `retake_limit_per_panel`（2回）まで。それでもダメなら一番ましな版を `image` に選び、最後に報告する

### 5. ページに仕上げる（status: pages）… 無料

1. `compose_page.py <作品> --all --debug` を実行し、`pages/pNN_debug.jpg`（10% 刻みの目盛り入り）を Read で見ながら、吹き出しの `pos`・`tail`、絵の `focus`・`zoom` を調整する（置き方のルールは [manga_yaml.md](manga_yaml.md)）
2. 最終の `pages/pNN.jpg` を Read で確認する: 吹き出しが顔を隠していない / 読む順が自然（右→左、上→下）/ 文字が読める / 同じページでキャラの見た目がそろっている
3. `open_file.py <作品>/pages` でページのフォルダを開き、「できあがりました。直したいところがあれば、『3ページ目の2コマ目の〜』のように教えてください。よければ『完成』と言ってください」と伝える

### 6. 修正の指示を受ける

直す範囲はできるだけ小さくする。「3ページ目の2コマ目」は `p03_02`（右上から数えた読む順）。

| 指示の例 | やること | 費用 |
|---|---|---|
| セリフを変えて / 吹き出しをずらして | manga.yaml を直して `compose_page.py --page N` | 無料 |
| このコマをもっと笑顔に | `--panels <id> --retake --extra "..."` → 再合成 | 1枚 |
| 前の絵の方がよかった | `panels/<id>*.png` の旧版から選んで `image` を書き換え → 再合成 | 無料 |
| 主人公の髪を短く | appearance を直して設定画を作り直す → そのキャラが出るコマを数え、**枚数と金額を伝えて了承を得てから** `--panels ... --retake` | 複数枚 |
| 4ページ目のコマ割りを変えて | layout を変え、コマ数を合わせる → `--info` で形が大きく変わるコマだけ作り直す | 数枚 |
| ページを1枚足して | ネームを足して確認 → 生成 | 数枚 |

- 旧版の画像は消さない
- 複数枚の作り直しは、おまかせモードでも枚数と金額を伝えてから行う
- 直したら、直したページを `open_file.py` で開いて見せる

### 7. Kindle 用に書き出す（status: exported）

ユーザーが「完成」「書き出して」と言ったら:

1. 表紙の絵がなければ `cover` に `scene` などを書き、`gen_panels.py <作品> --cover`（1枚）。タイトルは後から文字で入る
2. `export_kindle.py <作品>` → `check_epub.py <作品>/output/<file_name>.epub`。エラーがあれば直して書き出し直す
3. `output/preview_gray.jpg` を Read で見て、白黒の E-ink 端末でも人物と背景が見分けられるか確認する。見分けにくいページはユーザーに伝える
4. `open_file.py <作品>/output` で出力フォルダを開き、次を伝える:
   - `<file_name>.epub` が本文、`cover.jpg` が表紙。KDP にはこの2つをアップロードする
   - アップロード前に Kindle Previewer で `<file_name>.epub` を開いて確認する
   - KDP の登録画面で「AI 生成コンテンツ」を申告する（文章・画像とも AI 生成）
   - 生成枚数と費用（`gen_panels.py <作品> --usage`）

## おまかせモード

途中の確認をすべて省き、書き出しまで一気に進める。

- 足りない入力は質問せず Claude が補う。補った内容と、あらすじの解釈を `decisions` に書いておく
- ネームと設定画は自分でチェックして確定する（自己チェックは確認モードと同じ基準）
- 上限（終了コード 3）に達したら、そこで止めてユーザーに相談する
- 最後に報告する: 決めた内容（`decisions`）/ 生成枚数と費用 / 気になった点（作り直しの上限に達したコマなど）。完成ページと出力フォルダを開く
- 完成後の修正は確認モードと同じように受け付ける

## スキルを更新して

リポジトリ直下で `git pull` を実行し、結果をやさしく伝える（「最新の状態になりました」など）。
失敗したとき（手元の変更とぶつかったなど）は、無理に上書きせず「セットアップ担当の方に連絡してください」と伝える。

## 困ったとき

| 症状 | 対応 |
|---|---|
| `GEMINI_API_KEY が設定されていません` | 「API キーの設定が必要です。セットアップ担当の方に連絡してください」と伝える |
| `uv` が見つからない | 同上（uv のインストールが必要） |
| 画像が返らない（安全フィルタ） | `scene` の言い回しを変えて作り直す |
| API エラー 429（回数制限） | 1〜2分待ってから再実行 |
| Kindle Previewer で開けない | EPUB の保存場所に日本語が入っていないか確認 |
